# v0.6 — container × algorithm matrix and Frontend `/cookbooks` scope

## 1. What we are proving

Four execution classes, one cookbook contract:

| Class | Algorithm | Container / runtime | Dataset | Execution |
| --- | --- | --- | --- | --- |
| Optimizer | GEPA | Banking77 task container | Banking77 | local Workshop + terminal |
| Eval-only | none (evals engine) | HealthBench task container | HealthBench | local/API |
| Local train | SFT | MLX Tinker server + Craftax container eval | Craftax | macos-arm64 |
| Hosted train | CISPO | hosted job adapter + GSM8K eval | GSM8K | remote |

Containers stay in `synth-laboratories/containers`. Algorithms stay in Optimizers or the hosted CISPO adapter. Cookbooks only pin revisions and assemble runbooks.

## 2. Why these four pairs (and not others)

**GEPA × Banking77.** Lowest-latency exact-match task; dag policy; one mutable system prompt; already has durable rollouts and C-6 producer integrity in `old/cookbooks/optimizers/gepa/banking77_container`. MiniGrid/TBLite remain second-wave GEPA. Do **not** use the old Crafter GEPA cookbook as the SFT path — that is prompt ReAct, not weight training.

**Evals × HealthBench.** Separates scoring from search. `old/cookbooks/optimizers/gepa/healthbench_groq` is a GEPA-shaped eval; the v0.6 cookbook should call the eval/container contract without a proposer. Do not ship “GEPA on HealthBench” as the eval flagship.

**SFT × Craftax via MLX Tinker.** Local training flagship is long-horizon Craftax, not GSM8K. Train through the MLX Tinker API; evaluate through `synth_containers` Craftax (same env family as `/evals/craftax`). The cookbook must not copy `old/.../crafter_container`. Hero evidence should be replayable traces plus pre/post achievement or return, aligned with the public Craftax eval page rather than a math score.

**CISPO × GSM8K (hosted).** Stays a cheap hosted language-task proof. It is **not** the Craftax twin: local SFT shows Apple-silicon env training; hosted CISPO shows remote job/usage contracts. Do not force a shared GSM8K eval across those two lanes.

**Explicit non-goals for launch.** GELO; DungeonGrid as a cookbook (eval page already exists); HotpotQA/HoVer/FinQA/TAU2; GEPA-on-Crafter as the training demo.

## 4. Frontend research-page integration

Today:

- `/research` is MDX via `content-collections` (`content/research/**`).
- `/evals/craftax` (and GameBench, DungeonGrid) are first-class App Router pages with cached JSON matrices — this is the quality bar.
- Cookbooks are only a GitHub link on `/research` and `/oss`.
- Blog posts hard-code SHAs into `synth-cookbooks-public` paths (`1932ee78…/cookbooks/optimizers/gepa`).

Target:

```text
/cookbooks                 catalog (generated, not hard-coded cards)
/cookbooks/<slug>          detail (same IA for all four)
/research                  keep; add a “Runnable cookbooks” strip linking catalog
/evals/craftax             public matrix/traces; mlx-sft-craftax links here, does not replace it
/evals/*                   HealthBench cookbook links out; GameBench/DungeonGrid unchanged
```

### 4.1 Catalog (`/cookbooks`)

Ingest `catalog.v1.json` published from this repo (CI artifact or fetch-at-build from a pinned release). Do **not** duplicate listings in Frontend.

Card fields from the manifest: title, one-line outcome, method, task, runtime, local/hosted, time/cost band, Workshop compatibility, review status/date.

Filters: method, runtime, execution, hardware, cost, difficulty, status.

Search: title, summary, tags, task, method.

### 4.2 Detail (`/cookbooks/<slug>`)

Shared template (not four unrelated research posts):

1. Title, outcome, status, compatibility  
2. Hypothesis → verdict → confidence → why (from `REPORT.md` front-matter or `evidence.json`)  
3. Hero viz (lane-specific: GEPA Pareto/lineage; HealthBench score distribution; Craftax SFT loss + replay/achievements reusing `/evals/craftax` visual language; CISPO hosted metrics)  
4. Architecture (container + algo boxes; pins)  
5. Requirements / cost / hardware / credentials  
6. Quickstart + Open in Workshop + immutable download (revision + sha256)  
7. Results + traces (redacted)  
8. Provenance (cookbook digest, container/optimizer SHAs)  
9. Limitations  
10. Source path in this repo  

Implementation sketch:

- `frontend/content.config.ts`: optional `cookbooks` collection **or** load generated JSON at build (preferred so Workshop and site share one artifact).
- `frontend/src/app/(pages)/(public)/cookbooks/page.tsx`
- `frontend/src/app/(pages)/(public)/cookbooks/[slug]/page.tsx`
- Reuse Craftax-style charts only as *slot* components keyed by `classification.method`.
- Redirects: historical GitHub/blog cookbook URLs → `/cookbooks/gepa-banking77` (or a `deprecated` catalog row pointing at `old/` SHA).

### 4.3 Research page changes (small)

On `/research`:

- Change the Cookbooks OSS card href from GitHub root to `/cookbooks`.
- Add four launch tiles (status: reviewed/experimental) that read the same catalog.
- Keep GEPA/GELO *research* posts as narrative; they cite cookbook slugs instead of frozen tree paths.

Do not render full `REPORT.md` as a research MDX post. Research stays essay-shaped; cookbooks stay contract-shaped.

### 4.4 Trust and download

Frontend shows digest and review badge; Workshop performs verify-before-extract. Site download buttons must address `id + version + git sha + content_digest`, never `main`.
